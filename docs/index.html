strictest-setups

One folder per language carrying the strictest workable enforcement baseline: linting, type checking, docstring and comment rules, and a machine-enforced code-coverage gate at 95%. Every non-default choice carries its reason; every coverage gate has a recorded pass and fail proof.

Languages

rust/

  • clippy: pedantic, nursery, cargo + restriction picks — every deny carries a reason
  • [workspace.lints.rustdoc] all = "deny", missing_docs = "deny"
  • cargo llvm-cov --fail-under-lines 95

python/

  • ruff select = ALL, 18 documented ignores
  • mypy --strict + warn_unreachable
  • ruff D (google), fail_under = 95, branch coverage on

typescript/

  • typescript-eslint strictTypeChecked + jsdoc require/check
  • tsc strict + eight beyond-strict flags
  • vitest thresholds 95 × four axes

go/

  • golangci-lint v2: standard + gocritic, revive, misspell, …
  • revive exported as the doc-comment gate
  • go tool cover -func total ≥ 95 gate script

The gate that has teeth

A coverage gate that has never failed is unverified. Every folder's README records two real runs: covered fixture → passes, and the same fixture with one untested path → fails the build. 
$ cargo llvm-cov --workspace --fail-under-lines 95   # rust/
$ pytest                                             # python/ — coverage's fail_under = 95
$ npm test                                           # typescript/ — vitest thresholds 95 × 4 axes
$ ./coverage-gate.sh                                 # go/ — go tool cover -func total ≥ 95

Use it

# reference: read the folder for your language
# or run the init skill in your new repository
$ git clone https://github.com/PhillipChaffee/strictest-setups
$ strictest-setups/scripts/install-skills.sh     # installs init-rust-repo, init-python-repo, ...

The skill copies byte-identical templates (scripts/verify-sync.sh fails on drift), adapts the project name, runs every gate before the first commit, and refuses to continue if a toolchain cannot be installed or a gate cannot run.
